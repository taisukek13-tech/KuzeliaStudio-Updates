# Kuzelia Studio

配信録画から切り抜き・縦ショートを作るWindows 64ビット版アプリです。場面探し、字幕、見出し、構図、音声調整をPC内で行い、完成後に再生して確認できます。

[最新版の配布ページ](https://github.com/taisukek13-tech/KuzeliaStudio-Updates/releases/latest)

## インストール済みの方

アプリの「アプリを更新」→「最新版を確認・取得」→「更新して再起動」を使ってください。署名付きの更新で、素材・完成動画・作品設定・通常の設定を保持します。

通常の更新でZIPやセットアップを手動導入する必要はありません。アプリを終了できない、取得・適用に失敗する場合は、下の「困ったとき」を確認してください。

## 初めて使う方・アプリを修復する方

最新版の配布ページから、`KuzeliaStudio_Setup` で始まるEXEファイルを選びます。起動中のKuzelia Studioを終了してから実行してください。新規導入と修復用で、素材・作品・設定を削除する操作ではありません。修復にはインストール済みと同じ版か新しい版を使います。

ホームの「設定・AIの準備」で基本字幕AIと追加AIの状態を確認します。自動の場面選びには初回に追加AI約8.9GBが必要です。既存の4資産を使い、今回の改善で大型モデルを増やしていません。処理時間はPCと録画の尺で変わります。

## 最初の1本

1. 「録画を選んでAIで作る」、または「配信アーカイブからAIで作る」を選ぶ。
2. 使用する音声、保存先、本数を確認して「この録画から作成」を押す。
3. 完成動画を再生し、冒頭と結末、固有名詞、字幕の読みやすさ、構図、音を確認する。
4. 必要なら「字幕・構図を調整」から直し、投稿用のMP4を書き出す。

MP4は投稿・再生用、作品設定は編集を続けるためのファイルです。作品設定には元動画を含みません。元動画も保持してください。

## 改善版で使えること

- 自動字幕の「笑、」「（笑）」などの非発話表記を初期表示から除外。手入力と明示的な確認は保持し、保存済み作品にも再書き出しで反映。
- 確認済みの字幕を編集した場合は再確認。字幕用音声を直接変換し、完成動画の音量検査と全編デコードを統合。
- 検査ソフトが終了0を返しても、重要度付きのデコードエラーを見逃さないよう検査。

- 動画内の見出しと投稿タイトルを案として配置し、未承認の案は確認が必要と表示。
- 自動字幕の不要な話者表記・改行・長すぎる表示を整理。同じAIの別デコードだけで独立した認識との不一致を解除しない。
- 確認待ちの自動字幕は編集用の案として保持し、確認後に表示。編集画面では未確認の案の表示も選べる。
- 完了した音声認識と仕上げ応答を条件が一致する場合に再利用。字幕の裏づけが不足する場合の長い見出し再審査を省く。
- 終了表示を別指示でも確認できた勝負候補では追加観察を省き、解析結果を再利用できる段階では不要なAI起動を削減。
- 縦動画に元の横向きの画面比率情報が残る不具合を修正。旧プレビューは作り直し、その後は再利用。
- 複数本の自動作成、保存した制作の続きからの再開、完成一覧での検索。
- 一部の字幕時刻が崩れた場合、その短い区間だけを同じAIで一度再認識し、確認点を記録。
- 冒頭案の比較、保存済み比較の復元、評価の下書き、採用率・修正時間の集計。
- 前後の発言と映像の結末の照合、構図提案、重なり・読む速度の点検。
- 見出しを確定できない場合の自動構図の空白を整理し、ゲーム・字幕・アバターを再配置。手動の構図は保持。
- 30/60fps出力、任意のNVIDIA書き出しとCPUへの自動切り替え。
- AI保存先の移動、管理下の再利用データの容量確認・整理。
- 人が確認した正解字幕との比較、匿名の名前での動画比較、投稿実績CSV。

「アプリ判定」は編集上の確認点の点数です。人気・再生数の予測や、人が確認した字幕の正解率ではありません。未測定の数値や評価を0で埋めません。

構図提案と時系列画像の判定には誤りが残ります。ゲーム内の表示やアバターが欠けていないか再生して確認してください。混ざった音声からの自動話者判別・声の分離は行いません。独立したマイク音声があれば、その音声を使ってください。

フォントの利用条件・作者・必要なクレジットは、アプリの設定で確認できます。

## 困ったとき

- AIの準備に失敗：設定で保存先・空き容量を確認し、「保存したAIを確認」。途中の取得は再開できます。
- 制作を中止：完成済みの動画は保持します。「前回のAI制作を再開」、完成一覧、保存済みの作品設定を確認してください。
- 自動字幕が出ない：確認待ちの字幕案を残している場合があります。「字幕・構図を調整」で音を聞いて修正し、「確認済み」にしてください。「確認待ちの自動字幕も表示」で案も見ながら確認できます。
- 字幕・構図が違う：完成動画の冒頭と結末を確認し、調整画面で修正してください。別の候補を使うこともできます。
- 空き容量が少ない：設定から管理下の古い再利用データを整理できます。素材・完成動画・作品設定・AIモデルは対象外です。
- 更新できない：アプリを複数起動していないか、ファイルが使用中でないかを確認して再試行してください。更新ファイルを手動編集したり、保護機能を丸ごと無効にしたりする必要はありません。
- 起動できない：アプリを終了し、同じ版か新しい版のセットアップで修復してください。

詳しい手順はアプリの「使い方・困ったとき」、診断結果は「診断・不具合報告」から開けます。報告時はアプリの版、再現する操作、表示されたエラーを添えてください。素材や個人情報を公開する必要はありません。

## 検証範囲

0.18.5は実FFmpegを含む885項目、実音声認識37項目、GPU切替の模擬21項目、梱包16項目を通過。正常な音声が残った映像破損の検出と、確認用音声の失敗・中止時の保護を確認しました。同じ3場面を最終版で再出力し、表示字幕3/2/1件と画面内見出し・投稿タイトル案を保持しています。「笑、」は認識結果と既存作品での回帰検査で再現しており、利用者が問題を見つけた同じ完成動画での確認とは分けています。笑いの音響判定や、全ての字幕誤認識の解消ではありません。

同じ16秒を旧0.18.4と比較し、音声準備は各6回の中央値0.399→0.250秒、完成検査は各3回の中央値1.421→1.119秒でした。音量・ピークの計測値は一致。Linux共用CPUでの工程別測定で、録画全体・Windows・実GPUの短縮率ではありません。[0.18.5のWindows検証](https://github.com/taisukek13-tech/KuzeliaStudio-Updates/actions/runs/42078644907)も合格しました。既に作成済みのMP4へ反映するには、作品設定を開いて再書き出してください。

0.18.4では、同じ3場面を再出力し、表示できる発言字幕が各3/0/0件から3/2/1件になりました。3本とも動画内の見出しと投稿タイトル案を確認しました。短い発言中心のため字幕のない時間が残り、聞き取りが一致しなかった発言は編集用の案に残します。人が確認した字幕正解率や投稿品質は未測定です。

[0.18.4のWindows検証](https://github.com/taisukek13-tech/KuzeliaStudio-Updates/actions/runs/42062746587)で、画面27ケース、1080pの30/60fps出力、画素比率と表示比率、旧版からの更新・再起動、新規導入・修復・削除と利用者データ保持を確認しました。実GPUと利用者PCでの試験は今後の対象です。

16秒の映像のデコードと単色背景合成は中央値7.35秒から1.10秒になり、480フレームの画素が一致しました。字幕・エンコードを外したLinux共用CPUでの各3回測定です。字幕が出なかった2本の追加照合は初回合計約151秒、同条件での再作成は約5.4秒でした。全録画や実Windows・GPUの速度は別途の測定が必要です。



0.18.3は実FFmpegを含む867項目、GPU切替の模擬21項目、梱包16項目、実音声認識37項目を通過。381秒素材から実3本を作成し、全編デコードと画面比率、動画内タイトル、投稿タイトル案を確認しました。全3本に投稿前の確認点が残り、2本は表示できる確かな字幕がありません。未確認の字幕を表示しないことを、正解率の改善とは扱いません。

[0.18.3の最終Windows検証](https://github.com/taisukek13-tech/KuzeliaStudio-Updates/actions/runs/41986201626)も合格しています。

同じ381秒の素材から3本を再作成する試験は、5分9秒から1分52秒。3本のMP4はバイト単位で一致しました。解析結果を再利用するLinux共用CPUの各1回測定で、初回の全録画処理や実Windows・GPUの短縮率ではありません。

0.18.2は実FFmpegを含む843項目、GPU切替の模擬21項目、配布・ソース梱包用16項目を通過しました。[最終版のWindows検証](https://github.com/taisukek13-tech/KuzeliaStudio-Updates/actions/runs/41971749609)も合格しています。

Windows VMで9画面×3サイズの27ケース、1080pの30/60fps出力、NVIDIAが使えない場合のCPU切り替え、元動画・別録り音声・背景画像の差し替えとプレビュー再利用を確認しました。旧0.17.0の更新ヘルパーで署名付き813ファイルの置き換え・再起動を実行し、新規導入・修復・削除と素材・設定・追加フォントの保持も確認しています。

0.18.2での同じ27.3秒候補の映像判定は、解析キャッシュなし・同じ映像AI実装・CPU4スレッドの比較で12分31秒から6分45秒へ約46%短縮しました。Linux共用CPUの各1回測定で、全録画・Windows PC・実GPUの短縮率ではありません。AIモデルや画像の解像度は下げていません。

Windowsでは4本の出力をアプリと別のffprobeで調べ、画素比率1:1・表示比率9:16も確認しています。

Windowsの画面倍率は100%での検証です。実GPU、利用者PC、全DPI、物理キーボード操作、全ジャンルの採用率、人が確認した字幕正解率は未測定です。Windowsでの更新ヘルパー試験は、画面の更新ボタンからのネットワーク取得を含みません。

アプリ内更新のRSA署名と、Windowsのコード署名は別です。コード署名用の証明書は未設定のため、Windowsコード署名済みの配布物とは案内していません。

公開するのは実行用パッケージ・新規導入／修復用セットアップ・署名付き更新情報です。開発用ソース、秘密鍵、利用者の録画、内部の評価用データは含めません。
